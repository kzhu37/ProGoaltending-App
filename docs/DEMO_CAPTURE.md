# Authentic demo capture checklist

No application screenshot or screen recording is included in the repository yet. Only capture from a locally running app or an accessible Vercel deployment using the included fictional data.

## Capture set

1. **Home, mobile:** reset demo, open \`/\` at a mobile viewport; show the next session, active focus, and contextual action without private browser information.
2. **Booking, mobile:** open \`/book\`, choose the recommended training, select a location and a date. Capture the available-time list with counts generated by the demo. Optionally show the confirmation with the visible "Demo booking only" disclosure.
3. **Recap to Blueprint:** under \`/demo\`, choose **Recap Ready**, open \`/training/upcoming-primary\`, and show the proposed Blueprint change. Apply it and capture \`/blueprint\` afterward.
4. **Resource progress:** open \`/library\` or a resource detail route, complete one predetermined review, and capture the resulting progress state.
5. **Desktop context:** capture one centered desktop layout only if it communicates responsive behavior beyond the mobile views.

## Rules

- Reset the demo before each unrelated capture sequence.
- Do not edit screenshot pixels to alter the app's content or create nonexistent UI.
- Do not include personal identifiers, browser profile details, analytics panels, or real account information.
- Label all captured sessions, coaches, prices and feedback as fictional.
- Give each committed file descriptive alt text and a caption explaining what it proves.
- Keep original source capture files available locally when practical; never call a graphic reconstruction a screenshot.

Suggested paths after authentic capture: \`docs/media/home-mobile.webp\`, \`docs/media/booking-flow.webp\`, \`docs/media/recap-blueprint.webp\`. Update the README to embed only files that were actually captured and reviewed.
